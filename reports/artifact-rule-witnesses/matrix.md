# Artifact and explanation rules for admitted development families

The executable [results](results.json) come from `python3 -m studies.artifact_rule_witnesses`; [the generator](../../studies/artifact_rule_witnesses.py) derives truth from the case specifications and analytic reference equations, without a check selector. These are constructed development witnesses, not new artifact admissions, final labels or observed reviewer outcomes. The existing [Claude AI technical review and its exposure record](../reference-admission/README.md) admit the four base references at their stated scopes. This rule extension has not received a new scoped Claude review.
The later Kirsch row reuses the [admitted holed-plate values](../kirsch-reference/results.json) and its [separate review](../kirsch-reference/claude-review/README.md); the extension of R1 to R5 to that family has likewise not received a new scoped review.

A claim names an observable and unit, loading/boundary convention, ideal model and inclusive decision error. An artifact class declares whether the value is exact, serialized, solver-bounded or a printed display. The alternative-explanation set declares which implementation changes can be considered compatible with the available observations. A claim is sufficient only if every compatible explanation has the same independently calculated decision. Inconsistent evidence has no compatible explanation and cannot be called sufficient. [Existing axial claim and observation tolerances](../../studies/evidence_sufficiency/claims/spec.json), [other case contracts and numerical budgets](../../studies/reference_qualification/spec.json) and the [cylinder resolution rule](../../studies/cylinder_convergence/manifest.json) are the sole numeric homes; this report introduces no replacement budgets.

The route budget is numerical reproduction, not an application tolerance. |

Exact arithmetic witnesses use exact reference and output values. Serialized binary64 exact-route outputs have a separately declared one-ULP reproduction budget; that budget controls numerical encoding, not an engineering allowable or measurement uncertainty. The cylinder solver's characteristic-scale budget and registered convergence are numerical qualification, not a uniform physical error guarantee. A printed rounded target permits a value interval only when its rounding convention is specified; the source's unknown convention cannot certify a high-precision claim. No physical/application acceptance tolerance has been justified here, so no application-quality label is frozen.

[The registered cylinder result](../cylinder-convergence/matrix.md) remains the only home for its tested-input coverage. The `cylinder_registered_inputs` field in the JSON is an equality check against that record, not added coverage. VM92 is a regression of the prior [artifact-class demonstration](../vm92-artifact-evidence/matrix.md), not an extra problem. The [retained detectability sweep](../development-compute/matrix.md) was not rerun.

## Missing reference audit

The [Cornell wrong-physics paper](https://arxiv.org/abs/2605.09360) presents PDE-intent fidelity for MOOSE code. Its reported benchmark cases do not by themselves supply this project's chosen physical observable, boundary/load convention, independently derived numeric answer and claim budget. No exact case was imported or counted here. Its [arXiv distribution license](https://arxiv.org/licenses/nonexclusive-distrib/1.0/) does not itself grant repository reuse rights for its case materials. The available paper is methodological prior work, not a ready-made admitted mechanics or heat-transfer reference.

The [FEM-Bench repository](https://github.com/elejeune11/FEM-bench/tree/d370aef5dbe023b0b86eb3548d24d11fd69328ee/tasks) at `d370aef5dbe023b0b86eb3548d24d11fd69328ee` has an [MIT license](https://github.com/elejeune11/FEM-bench/blob/d370aef5dbe023b0b86eb3548d24d11fd69328ee/LICENSE). The inspected [Q8 edge-load task](https://github.com/elejeune11/FEM-bench/blob/d370aef5dbe023b0b86eb3548d24d11fd69328ee/tasks/FEM_2D_quad8_element_distributed_load_CC0_H0_T0.py) specifies nodal load assembly for a constant edge traction. It does not specify a complete boundary-value solution, a claim-specific physical verification decision, or an independently qualified result for this benchmark. Its reference implementation and tests cannot be substituted for a separate derivation. The 1D linear-elastic tasks overlap the existing axial family. No FEM-Bench task was counted merely because code and tests are available.

No fifth base problem is admitted. The missing input is a distinct source specification with geometry, loading, constraints, observable, convention and reuse rights, plus an independently derived cross-check and scoped Claude AI technical review. The provisional coverage target and M1.3 label-freeze prerequisites remain open. This audit made no new research campaign or reserved-case access.
